# Data Model: Shared Grocery List

**Date**: 2026-11-06  
**Feature**: [Shared Grocery List](spec.md)

## Design Goals

- Keep one deployment's shared list as a small, readable document.
- Make every mutation serialized, atomic, durable, and safe to retry.
- Distinguish duplicate item names through stable identifiers.
- Derive creator attribution exclusively from the authenticated server session.
- Store no purchase history, behavioral data, profile records, or unnecessary metadata.

## Domain Entities

### GroceryItem

An active item that remains on the shared shopping list.

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID string | Required, unique within the list, generated by the backend, immutable. |
| `text` | string | Required, trimmed, 1–200 characters, no CR/LF or disallowed control characters. Duplicate values are allowed. |
| `creatorName` | string | Required, non-empty display name taken from the authenticated Google session, immutable. Never accepted from request input. |

The MVP intentionally stores no quantity, category, price, ownership, timestamp, bought flag, or
history. Marking an item bought removes it from the active collection.

### ShoppingList

The authoritative state owned by one named Durable Object.

| Field | Type | Rules |
|-------|------|-------|
| `schemaVersion` | integer | Required; initially `1`; permits explicit future migrations. |
| `revision` | non-negative integer | Required; increases once for each newly processed mutation, including safe no-op mutations. |
| `items` | ordered `GroceryItem[]` | Required; contains active items only. Addition appends to the end. |

`remainingCount` is derived as `items.length` and is never stored separately.

### SessionClaims

Encrypted claims in the fixed-lifetime CartMates session cookie.

| Field | Type | Rules |
|-------|------|-------|
| `v` | integer | Session format version; initially `1`. |
| `sub` | string | Stable Google subject identifier. |
| `email` | string | Normalized verified Google email; checked against the current allowlist on every protected request. |
| `name` | string | Non-empty Google display name used for new-item attribution. |
| `csrf` | random string | Secret token required on state-changing requests. |
| `iat` | integer | Issued-at time. |
| `exp` | integer | Fixed expiry, 24 hours after issue. |

The session is an authenticated encrypted JWE in a Secure, HttpOnly, host-only cookie. Provider
access and refresh tokens are not retained.

### OAuthTransaction

Short-lived encrypted state used only while completing Google sign-in.

| Field | Type | Rules |
|-------|------|-------|
| `state` | random string | One-time CSRF correlation value. |
| `nonce` | random string | One-time ID-token replay correlation value. |
| `codeVerifier` | PKCE verifier string | Used for the server-side code exchange. |
| `returnPath` | local path | Validated local post-login destination; defaults to `/`. |
| `iat` | integer | Issued-at time. |
| `exp` | integer | Ten minutes after issue. |

The transaction is consumed once at the callback and never persisted in list storage.

### MutationCommand

The trusted command sent from a Pages Function to the Durable Object after authentication,
authorization, CSRF, origin, content-type, and input validation.

| Field | Type | Rules |
|-------|------|-------|
| `operationId` | UUID string | Taken from the validated `Idempotency-Key` request header. |
| `kind` | enum | `add`, `remove`, `markBought`, `clear`, or `markAllBought`. |
| `actorSub` | string | Derived from the authenticated session; never supplied by browser JSON. |
| `actorName` | string | Derived from the authenticated session; used only by `add`. |
| `itemId` | UUID string or absent | Required for `remove` and `markBought`; absent otherwise. |
| `text` | string or absent | Required for `add`; absent otherwise. |

A deterministic fingerprint covers `kind`, `itemId`, and normalized `text`. Identity is already
scoped by `actorSub` in the receipt key.

### OperationReceipt

A minimal durable record proving how one mutation attempt was resolved.

| Field | Type | Rules |
|-------|------|-------|
| `kind` | mutation kind | Required. |
| `fingerprint` | string | Required; detects reuse of an idempotency key for a different request. |
| `outcome` | enum | `applied`, `already_absent`, or `already_empty`. |
| `revision` | non-negative integer | Revision produced by the original processing. |

The storage key is `operation/<actorSub>/<operationId>`. Receipts contain no grocery text,
creator name, email, or list snapshot. MVP receipts are retained indefinitely so a delayed retry of
a list-wide operation can never affect items added after the original operation.

### GroupConfiguration

Deployment configuration rather than persisted application data.

| Setting | Source | Rules |
|---------|--------|-------|
| `GROUP_DISPLAY_NAME` | non-secret environment variable | Defaults to `Our Groceries`. |
| `ALLOWED_EMAILS` | encrypted secret | Static normalized allowlist; never returned to clients. |
| `APP_ORIGIN` | non-secret environment variable | Exact canonical origin; not hardcoded to the initial production domain. |
| `GOOGLE_CLIENT_ID` | environment variable | OAuth client identifier. |
| `GOOGLE_CLIENT_SECRET` | encrypted secret | Server-only. |
| `SESSION_ENCRYPTION_KEY` | encrypted secret | Server-only AES-GCM key material. |
| `LIST` | external Durable Object binding | Points to the private `SharedList` class. |

## Persistence Representation

The Durable Object stores the list under `state/document` as newline-delimited JSON. A metadata
record comes first, followed by one record per active item in display order.

```ndjson
{"type":"meta","schemaVersion":1,"revision":42}
{"type":"item","id":"68b9432d-cf6e-4d86-a841-4b56361510a7","text":"Milk","creatorName":"Hagay"}
{"type":"item","id":"164f9514-e7fe-4ed2-8c2f-bda4924af4dc","text":"Eggs","creatorName":"Dana"}
```

An absent `state/document` is interpreted as an empty version-1 document at revision zero. Parsing
is strict: unknown record types, invalid fields, duplicate IDs, multiple metadata records, or an
unsupported schema version fail safely instead of silently repairing or overwriting data.

## Invariants

1. The Durable Object is the sole authoritative owner and mutation boundary for the list.
2. Every active item ID is unique even when item text and creator names are identical.
3. Creator attribution is assigned during `add` from `SessionClaims.name` and never changes.
4. Every accepted mutation is processed in one storage transaction that writes both the new list
   document and its receipt before success is returned.
5. A known receipt returns the current authoritative list without applying the command again.
6. Reuse of an operation ID with a different fingerprint fails with an idempotency conflict.
7. Missing-item remove and bought commands never remove a different item.
8. No response is treated as committed by the client until the backend confirms it.
9. Durable storage, not object memory or browser state, survives eviction, restarts, and deployment.

## State Transitions

| Command | Preconditions | Atomic transition | Outcome |
|---------|---------------|-------------------|---------|
| Add | Valid text; authenticated actor name | Generate item ID, append item, increment revision, save document and receipt | `applied` |
| Remove | Valid item ID | If present, remove exactly that ID; increment revision; save document and receipt | `applied` or `already_absent` |
| Mark bought | Valid item ID | Same state transition as Remove; no history record | `applied` or `already_absent` |
| Clear | None | Remove all current items, increment revision, save document and receipt | `applied` or `already_empty` |
| Mark all bought | None | Same state transition as Clear; no history record | `applied` or `already_empty` |
| Retry known command | Matching receipt fingerprint | Do not mutate; load and return current document | Original outcome, marked as already processed |
| Reused key conflict | Receipt fingerprint differs | Do not mutate | Structured `409 idempotency_conflict` error |

Safe no-op commands receive a receipt and advance the revision when first processed. This makes the
serialization order observable and guarantees that a retry remains a no-op even if the list changes
later.

## Concurrency and Durability

All calls for the one deployed group resolve the same named Durable Object (`shared-list-v1`). The
object serializes commands. Each command uses one synchronous storage transaction, so concurrent
additions both survive and Clear/Add races resolve according to the backend's actual order. Reads
and mutation responses include the committed revision and full authoritative list. Clients replace
their local view with that response and use revision-based ETags for subsequent polling.
